# Адаптация Carbon Design System в Aramid

Гайд для разработчиков и агентов: как переносить компоненты и паттерны из **@carbon/react** (и при необходимости смежных пакетов Carbon) в пакет **@miracle/aramid**, сохраняя осмысленное поведение и снижая сложность под небольшой продукт.

См. также: [AGENTS.md](./AGENTS.md) (язык документации и комментариев в `aramid`).

---

## 1. Назначение и область

**Зачем этот документ.** Чтобы при добавлении нового компонента не повторять одни и те же правила: что выкидывать из Carbon, как оформлять стили и токены, как не потерять доступность.

**Откуда брать эталон.** Исходный API и поведение — по документации и коду **Carbon React**; целевая реализация — в **aramid**, с упрощениями, согласованными с продуктом (например, один десктопный уровень сетки без `sm` / `md` / `lg` в публичном API).

**Типы компонентов.** Правила ниже относятся ко всем категориям:

| Категория | Примеры в духе Carbon | На что опираться в aramid |
|-----------|------------------------|---------------------------|
| **Layout** | Grid, Column | CSS Grid, subgrid, переменные `--grid-*` / `--col-*` |
| **Visual** | Tag, Tile, типографика рядом с иконкой | Токены цвета и типографики (`tokens/color`, `tokens/typography`), CSS Modules |
| **Interactive** | Button, TextInput, Modal, Menu | Пропсы состояния, фокус, клавиатура, ARIA — не «оптимизировать» до поломки |

**Успешная адаптация:** меньше ветвлений и режимов, чем в Carbon, но предсказуемое поведение, русские комментарии к публичному API, согласованные токены и стили.

## 3. Токены (Style Dictionary)

**Где лежат исходники.** Каталог [`tokens/`](./tokens): JSON в формате DTCG (`$value`, `$type`, при необходимости `$description`).

**Сборка.** Команда `npm run build:tokens` ([`style-dictionary.config.mjs`](./style-dictionary.config.mjs)) генерирует:

- [`dist/css/tokens.css`](./dist/css/tokens.css) — переменные с префиксом **`aramid`** на `:root` (например `--aramid-spacing-5`);
- [`dist/js/tokens.mjs`](./dist/js/tokens.mjs) — ES-модуль с константами для JS (при необходимости).

**Правило переиспользования.** Сначала опираться на уже существующие токены (`spacing.*`, `breakpoint.*`, `color.*`, `typography.*`), затем вводить узкоспециализированные группы (`grid.*`, `column.*`, в будущем — `button.*` и т.д.).

**Пример:** сетка ссылается на отступы через `{spacing.N}`:

```json
{
  "grid": {
    "gutter": {
      "$value": "{spacing.5}",
      "$type": "dimension",
      "$description": "Межколоночный зазор wide / narrow."
    }
  }
}
```

Файл: [`tokens/grid/base.json`](./tokens/grid/base.json). Значение, не попадающее в шкалу spacing (например `1px` для condensed), задаётся отдельным токеном (`gutterCondensed`).

**Когда новый файл токенов.** Имеет смысл добавить `tokens/<компонент>/base.json`, если появляется **устойчивая группа** значений, которые переиспользуются в CSS и не сводятся к уже существующим `spacing` / `color` без потери смысла.

## 4. CSS variables: два слоя

**Идея.** Разделить:

1. **Прокидываемые из React** — имена **без** префикса пакета в смысле «бренда aramid в имени»: локальные контракты компонента, например `--grid-*`, `--col-*`, `--subgrid-*`. Их выставляет компонент в `style`, отражая пропсы и вычисления.
2. **Дизайн-токены** — после сборки Style Dictionary это **`--aramid-*`** в `tokens.css`; в CSS-модуле они используются как **fallback**, если инлайн не переопределил прокинутую переменную.

**Пример (Grid):** в TS задаются «прокинутые» переменные и часть значений ссылается на токены через `var(--aramid-...)`:

```ts
const vars: Record<string, string> = {
  '--grid-cols': '16',
  '--grid-column-gap': 'var(--aramid-grid-gutter)',
  '--grid-row-gap': withRowGap ? 'var(--aramid-grid-gutter)' : '0px',
  '--grid-padding-inline': narrow ? '0' : 'var(--aramid-grid-margin)',
  '--grid-max-width': fullWidth ? '100%' : 'var(--aramid-grid-max-width, 1584px)',
  // ...alignMargins(props.align) → --grid-margin-inline-start/end
};
```

Фрагмент из [`src/components/Grid/Grid.tsx`](./src/components/Grid/Grid.tsx).

**Пример:** раскладка читает сначала прокинутое, потом токен:

```css
.aramid-grid {
  grid-template-columns: repeat(var(--grid-cols, var(--aramid-grid-cols)), 1fr);
  column-gap: var(--grid-column-gap, var(--aramid-grid-gutter));
  padding-inline: var(--grid-padding-inline, var(--aramid-grid-margin));
}
```

Файл: [`src/components/Grid/aramid-grid.css`](./src/components/Grid/aramid-grid.css).

**Column:** прокидываются `--col-span`, `--col-start`, `--col-end`; в модуле fallback на токен дефолтного span:

```css
.aramid-column {
  grid-column: var(--col-start, auto) /
    var(--col-end, span var(--col-span, var(--aramid-column-span-default)));
}
```

См. [`src/components/Column/aramid-column.css`](./src/components/Column/aramid-column.css) и [`tokens/column/base.json`](./tokens/column/base.json).

## 5. Компоненты: структура файлов

**Рекомендуемый скелет** для компонента `Foo`:

```text
src/components/Foo/
  Foo.tsx           — логика, пропсы, инлайн-переменные при необходимости
  `aramid-*.css` — стабильные префиксованные классы + правила с `var(...)` (без CSS Modules: совместимость с tsup)
  FooContext.tsx  — только если нужен контекст (как у Grid / subgrid)
  index.ts        — реэкспорт публичного API
```

**Практика в репозитории:**

- [`src/components/Grid/`](./src/components/Grid/) — `Grid.tsx`, `aramid-grid.css`, `GridContext.tsx`, `index.ts`;
- [`src/components/Column/`](./src/components/Column/) — `Column.tsx`, `aramid-column.css`, `index.ts`.

**Полиморфный корень (`as`).** Если в Carbon компонент принимает `as`, в aramid сохраняйте контракт через [`PolymorphicComponentPropWithRef`](./src/internal/PolymorphicProps.ts), если нет веской причины упростить до фиксированного `div`.

**`displayName`.** Задавайте для `forwardRef`-компонентов — удобнее отладка и документация в DevTools.

## 6. Интерактивные компоненты

**Что нельзя «выкинуть ради простоты».**

- Управление с **клавиатуры** (Tab, Enter/Escape, стрелки — по смыслу виджета).
- **Фокус:** видимый outline или эквивалент в дизайне aramid; ловушка фокуса в модалках, если поведение Carbon это предполагало.
- **ARIA:** роли, `aria-expanded`, `aria-controls`, подписи к полям (`aria-label` / связь с `<label>`) — переносить или явно заменять эквивалентом, а не удалять без заметки в PR.

**Что можно упростить.**

- Лишние визуальные варианты размеров (только что связано с media query), если продукт использует один-два.
- Зависимость от глобальных Carbon feature flags, если в aramid фиксирован один режим.

**Короткий чеклист a11y при переносе интерактива:**

1. Свериться с документацией Carbon по роли и клавиатуре для этого паттерна.
2. Проверить порядок фокуса и возврат фокуса после закрытия (модалки, меню).
3. Не удалять `disabled` / `readOnly` и связанные стили без замены.
4. Для кастомных контролов — минимум: кликабельный элемент — `<button>` или роль + обработка клавиши по таблице WAI-ARIA.

## 7. Визуальные и презентационные компоненты

**Токены.** Цвета и типографика — из [`tokens/color/`](./tokens/color) и [`tokens/typography/`](./tokens/typography); в CSS компонентов ссылаться на `--aramid-*` из собранного `tokens.css`.

**Размеры и отступы.** По возможности выражать через `{spacing.N}` в JSON или через уже сгенерированные `--aramid-spacing-*` в CSS, чтобы не плодить «магические числа».

**Пример связки токен → CSS** (идея для будущего компонента, например «бейдж»):

```json
{
  "tag": {
    "paddingInline": { "$value": "{spacing.3}", "$type": "dimension" }
  }
}
```

```css
.tag {
  padding-inline: var(--tag-padding-inline, var(--aramid-tag-padding-inline));
}
```

Инлайн из React при необходимости переопределяет `--tag-padding-inline`.

## 8. Что выкидывать из Carbon

Типичные кандидаты на удаление или схлопывание в aramid:

- **Брейкпоинтные ветки** в публичном API (`sm` / `md` / `lg` на одном и том же пропе), если продукт только для десктопа — заменить **одним** именованным параметром (как `span` у Column) или фиксированными токенами «максимального» брейкпоинта.
- **FlexGrid** и прочие режимы, если в aramid договорён только **CSS Grid** (как у текущего Grid).
- **Длинные цепочки BEM-классов** с префиксом Carbon (`cds--…`) — заменить на **один префиксованный класс** `aramid-*` плюс **CSS variables** для вариантов.
- **Неиспользуемый контекст** (режимы `flexbox` / `css-grid` одновременно), если в коде остаётся один путь.

**«До / после» (схематично):**

```tsx
// Carbon-стиль: много модификаторов в className
<div className={cx(`${prefix}--grid`, { [`${prefix}--grid--narrow`]: narrow })} />

// Aramid: системный класс + переменные
<div className="aramid-grid" style={rootGridVariables(props)} />
```

**Breaking change.** Если меняются публичные пропсы или имена CSS-переменных, явно описать в PR и при необходимости обновить этот гайд.

## 9. Как находить «лишнюю» логику

**Признаки в исходнике Carbon:**

- Огромные `switch` / цепочки `if` по **режиму сетки** или **ширине viewport**.
- Генерация **десятков классов** из одного префикса.
- Дублирование одних и тех же чисел (gutter, columns) в разных брейкпоинтах без отличий для вашего продукта.

**Что делать.**

- Вынести стабильные значения в **токены** и один слой **переменных** в CSS.
- Оставить в TS только то, что действительно зависит от **пропсов** (например выравнивание через `--grid-margin-inline-start` / `end` в [`Grid.tsx`](./src/components/Grid/Grid.tsx)).

**Пример упрощения:**

```tsx
// Было: разные классы на каждый режим
if (condensed) classes.push(`${prefix}--condensed`);

// Стало: одно значение в переменной
'--grid-column-gap': mode === 'condensed'
  ? 'var(--aramid-grid-gutter-condensed)'
  : 'var(--aramid-grid-gutter)';
```

## 10. Тесты и сборка

После правок в `tokens/**/*.json`:

```bash
npm run build:tokens
```

Затем убедиться, что в [`dist/css/tokens.css`](./dist/css/tokens.css) появились ожидаемые `--aramid-*` и что CSS-модули ссылаются на существующие имена.

Проверка типов пакета:

```bash
npx tsc --noEmit
```

(из каталога `aramid`.)

## 11. Чеклист перед PR

- [ ] Публичные пропсы и поведение согласованы с Carbon **там, где это нужно**; лишние режимы удалены осознанно.
- [ ] JSDoc и пользовательские тексты — **на русском** ([AGENTS.md](./AGENTS.md)).

- [ ] Новые или изменённые значения в **`tokens/`**; где возможно — **`{spacing.N}`** и существующие группы токенов.
- [ ] **`npm run build:tokens`** выполнен; ссылки в CSS на `--aramid-*` актуальны.
- [ ] Для **интерактива**: фокус, клавиатура, ARIA проверены по чеклисту раздела 6.

- [ ] При появлении **нового устойчивого правила** адаптации — дополнить этот файл коротким подпунктом (не дублировать README целиком).
