Типичная ситуация при первом знакомстве с Effect: на руках уже есть масса рабочих инструментов на промисах — клиенты баз данных, HTTP-обёртки, облачные SDK. Возникает вопрос: всё переписать или как-то ужиться? Хорошая новость в том, что переход — не «всё или ничего». Промис заворачивается в Effect одной строкой, а библиотеки прячутся за тонкими адаптерами. Эта лекция показывает, как именно — от единичного вызова до stateful-клиента. Она продолжает лекцию о пайплайнах задач, где сервис Llm как раз и был такой обёрткой над промисным SDK.

1Промис уже запущен, Effect — ещё нет

Первое, что нужно усвоить, — глубинная разница между промисом и эффектом. Промис «горячий»: в момент создания связанное с ним действие уже стартовало. const p = fetch(url) — запрос ушёл, отменить или повторить его как значение нельзя. Effect «холодный»: это лишь описание, которое ничего не делает, пока его не запустят. Поэтому его можно повторять, прерывать, комбинировать.

Практическое следствие, из-за которого ломаются первые попытки: оборачивать в Effect нужно не промис, а функцию, которая его создаёт. Иначе действие запустится сразу и преимущества «холодности» потеряются.

Неверно: промис уже создан

const p = fetch(url);            // запрос УЖЕ ушёл
Effect.tryPromise(() => p);     // обернули запущенное —
                              // повтор/отмена уже не работают

Верно: оборачиваем функцию

Effect.tryPromise(() => fetch(url));
// действие стартует только при запуске эффекта,
// поэтому его можно повторять и прерывать

2Обернуть вызов: tryPromise и promise

Есть два конструктора, и выбор между ними — это решение «может ли вызов упасть».

import { Effect, Data } from 'effect';

// промис, который МОЖЕТ отклониться → ошибку ловим в типизированный канал E
class NetworkError extends Data.TaggedError('NetworkError')<{ cause: unknown }> {}

const getJson = Effect.tryPromise({
  try: () => fetch(url).then((r) => r.json()),
  catch: (cause) => new NetworkError({ cause }),   // отказ промиса → наша ошибка
});                                            // Effect<unknown, NetworkError>

// промис, который НЕ должен отклоняться (отказ = дефект программы)
const readClock = Effect.promise(() => clock.now());  // Effect<Date>
Почему именно такБез catch отказ промиса осел бы в типе как абстрактная ошибка; передав catch, мы переводим любой отказ в осмысленную ошибку домена — её видно в сигнатуре и нельзя молча проигнорировать. Это первый шаг к тому, чтобы ошибки перестали «теряться», как теряются в необработанном await.

3Функция-промис → функция-Effect

Любую функцию, возвращающую промис, превращаем в функцию, возвращающую Effect: тело остаётся прежним, меняется только обёртка. Это и есть базовая единица миграции — мигрируем по одной функции.

Было

function loadUser(id: string): Promise<User> {
  return api.get(`/users/` + id);
}

Стало

const loadUser = (id: string) =>
  Effect.tryPromise({
    try: () => api.get<User>(`/users/` + id),
    catch: (e) => new ApiError({ cause: e }),
  });

4async/await → Effect.gen

Когда у вас цепочка из нескольких await, переписывание почти механическое: async function становится Effect.gen(function* ...), а каждый await x — это yield* x (где x уже обёрнут в Effect по правилам разделов 2–3).

Было: async/await

async function checkout(id) {
  const cart  = await loadCart(id);
  const price = await quote(cart);
  const order = await pay(price);
  return order;
}

Стало: Effect.gen

const checkout = (id) => Effect.gen(function* () {
  const cart  = yield* loadCart(id);
  const price = yield* quote(cart);
  const order = yield* pay(price);
  return order;
});
ПодсказкаСтруктура кода сохраняется один-в-один, поэтому строки читаются так же сверху вниз. Разница лишь в том, что результат — это значение-эффект: его теперь можно повторить, прервать или обернуть в таймаут, не трогая тело.

5try/catch/finally → catch и ensuring

Императивная обработка ошибок переезжает на комбинаторы. Перехват по типу — catchTag; перехват всего — catchAll; гарантированная очистка (аналог finally) — ensuring, причём финализатор сработает и при ошибке, и при прерывании.

Было

try {
  return await risky();
} catch (e) {
  return fallback;
} finally {
  cleanup();
}

Стало

risky().pipe(
  Effect.catchAll(() => Effect.succeed(fallback)),
  Effect.ensuring(Effect.sync(() => cleanup())),
);

6Promise.all и Promise.race

Параллельные комбинаторы тоже имеют прямые аналоги — но с важным выигрышем: степенью параллелизма можно управлять, а при сбое одной ветви остальные корректно прерываются.

// Promise.all([a, b, c])  →
Effect.all([a, b, c]);                          // по умолчанию последовательно
Effect.all([a, b, c], { concurrency: 'unbounded' }); // как Promise.all
Effect.all(tasks, { concurrency: 5 });           // не больше пяти одновременно

// Promise.race([a, b])  →
Effect.race(a, b);                              // проигравшая ветвь будет прервана
Чего не умеет Promise.allУ Promise.all нет ограничения степени параллелизма (ставите тысячу запросов — уйдут все сразу), а отклонение одного промиса не останавливает остальные — они продолжают работать «в пустоту». Effect.all решает обе проблемы по умолчанию.

7setTimeout, ручной повтор и таймаут

Самописные задержки, циклы повторов и «гонки с таймером» — частый рукотворный код вокруг промисов. В Effect это готовые комбинаторы.

Было: руками

// задержка
await new Promise((r) => setTimeout(r, 1000));

// таймаут — гонка с таймером
await Promise.race([work, timer(5000)]);

// повтор — цикл с try/catch и счётчиком

Стало: комбинаторы

import { Effect, Schedule } from 'effect';

Effect.sleep('1 second');
work.pipe(Effect.timeout('5 seconds'));
work.pipe(Effect.retry(
  Schedule.exponential('200 millis').pipe(
    Schedule.compose(Schedule.recurs(4)))));

8Отмена: проброс AbortSignal в библиотеку

Главный вопрос при оборачивании промис-библиотек: что произойдёт с уже летящим запросом, если Effect прервут? Сам по себе промис прервать нельзя. Но многие библиотеки (fetch, axios, облачные SDK) принимают AbortSignal. Effect передаёт такой сигнал прямо в функцию try, и при прерывании эффекта сигнал срабатывает — библиотека отменяет операцию по-настоящему.

const getJson = Effect.tryPromise({
  try: (signal) => fetch(url, { signal }),   // Effect отдаёт сюда AbortSignal
  catch: (cause) => new NetworkError({ cause }),
});
// если этот эффект прервут (таймаут, race, отмена) — fetch получит abort
Если библиотека не умеет AbortSignalТогда отмена эффекта остановит ожидание результата, но фоновую работу библиотека продолжит — обещание не пропадёт. Это не катастрофа, но об этом нужно знать: «прервал эффект» не всегда равно «остановил действие». По возможности выбирайте методы с поддержкой сигнала.

9Колбэчные API → Effect.async

Не всё в экосистеме — промисы. Старые библиотеки и узлы событий работают на колбэках. Их заворачивает Effect.async: вы получаете функцию resume, которой сообщаете об успехе или ошибке, и можете вернуть эффект-очистку для прерывания.

const readFile = (path: string) =>
  Effect.async<Buffer, ReadError>((resume) => {
    fs.readFile(path, (err, data) => {
      if (err) resume(Effect.fail(new ReadError({ cause: err })));
      else     resume(Effect.succeed(data));
    });
    // при желании вернуть Effect-очистку, который вызовут при прерывании
  });

10Ресурсы и клиенты: acquireRelease и Layer.scoped

Многие библиотеки дают ресурс с жизненным циклом: соединение с базой, пул, файловый дескриптор, веб-сокет. Их нужно надёжно закрывать — даже при ошибке и прерывании. За это отвечает acquireRelease: пара «захватить / освободить», привязанная к области видимости (англ. scope).

const connection = Effect.acquireRelease(
  Effect.promise(() => pool.connect()),          // захват
  (conn) => Effect.promise(() => conn.close()),    // освобождение — гарантировано
);

// использовать в пределах области; по выходе соединение закроется само
const program = Effect.scoped(Effect.gen(function* () {
  const conn = yield* connection;
  return yield* Effect.promise(() => conn.query(sql));
}));
Почему это лучше try/finallyРучной finally легко забыть или не довести при вложенных ресурсах. acquireRelease делает освобождение частью значения: какой бы путь ни выбрала программа — успех, ошибка, прерывание — финализатор гарантированно отработает в правильном порядке.

11SDK как сервис: обёртка через Context и Layer

Это кульминация для нашего случая. Не нужно «обиффектить» каждый вызов SDK по месту. Правильнее один раз описать сервис — тег с интерфейсом, методы которого возвращают эффекты, — а конкретную реализацию-адаптер над промисным SDK подключить слоем. Дальше весь код зависит от тега, а не от библиотеки.

import { Context, Effect, Layer, Data } from 'effect';

// 1) интерфейс домена в терминах Effect (никаких промисов наружу)
class Llm extends Context.Tag('Llm')<Llm, {
  submit(req: SubmitReq): Effect.Effect<string, LlmError>;
  poll(opId: string): Effect.Effect<PollResult, LlmError>;
}>() {}

// 2) адаптер над промисным SDK — здесь, и только здесь, живут промисы
const LlmLive = Layer.succeed(Llm, {
  submit: (req) => Effect.tryPromise({
    try: (signal) => sdk.createOperation(req, { signal }),
    catch: (cause) => new LlmError({ cause }),
  }),
  poll: (opId) => Effect.tryPromise({
    try: (signal) => sdk.getOperation(opId, { signal }),
    catch: (cause) => new LlmError({ cause }),
  }),
});

// 3) прикладной код знает только тег — SDK невидим
const ask = Effect.gen(function* () {
  const llm = yield* Llm;
  return yield* llm.submit(req);
});
Связь с проектомИменно так сервис Llm из первой лекции и появляется: промисный Yandex/OpenAI-клиент прячется за адаптером-слоем. Если клиент имеет жизненный цикл (создаётся/закрывается), вместо Layer.succeed берут Layer.scoped и собирают его через acquireRelease (раздел 10). В связке с NestJS этот слой строит обычная фабрика-провайдер.

12Как мигрировать постепенно

Переписывать всё разом не нужно и вредно. Effect отлично сосуществует с промисами; держитесь нескольких правил.

  • Оборачивайте на границе. Промис-библиотеки прячьте за сервисами (раздел 11); внутри домена работайте уже с эффектами. Граница тонкая и в одном месте.
  • Мигрируйте от листьев к корню. Сначала превращайте в Effect самые нижние функции-обёртки вызовов, затем — то, что их вызывает. Так типы естественно «протекают» вверх.
  • Промис на самом краю. Там, где Effect должен встретиться со старым промисным миром (контроллер, обработчик, тест), запускайте его через Effect.runPromise — и снаружи снова обычный await.
  • Не «обиффичивайте» чистые функции. Синхронный код без побочных эффектов и без возможности упасть в Effect заворачивать не нужно — он и так композируется.
// Effect → Promise на краю системы (контроллер, тест, интеграция со старым кодом)
const user = await Effect.runPromise(loadUser(id).pipe(Effect.provide(ApiLive)));
Образ для запоминания«Функциональное ядро, императивная оболочка». Внутри — эффекты: композируемые, типизированные, прерываемые. По краям — тонкий слой, где эффект запускается в промис, а промис библиотеки заворачивается в эффект. Мигрировать можно годами по одной функции — и всё это время система остаётся рабочей.
