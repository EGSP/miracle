## Страница `/product-types`

Простой CRUD-справочник. Структура аналогична FilesPage.

```
┌─ Типы продукции ────────────────────────────────────────┐
│  [+ Создать тип]                                        │
│                                                         │
│  ┌─ НЭМС ───────────────────────────────────────────┐  │
│  │  Синонимы: муфта, НЭМС, электроизолирующее...   │  │
│  │                                          [Ред.] │  │
│  └──────────────────────────────────────────────────┘  │
│                                                         │
│  ┌─ Втулка ──────────────────────────────────────────┐  │
│  │  Синонимы: втулка, изолирующая вставка           │  │
│  │                                          [Ред.] │  │
│  └──────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────┘
```

**Компонент `ProductTypeCard`** (`front/src/components/blocks/product-type-card/`):
- Inline редактирование name и synonyms (по кнопке Ред.)
- synonyms — теговый инпут: ввёл текст, нажал Enter — добавил тег, крестик — удалил
- Сохранение через PATCH `/product-types/:id`

**Теговый инпут для synonyms:**
В shadcn/ui нет готового. Реализовать как `TagInput` компонент:
`front/src/components/ui/TagInput.tsx` — input + список тегов-пилюль рядом.

```
┌─ Технические условия ───────────────────────────────────┐
│  [+ Создать ТУ]                                         │
│                                                         │
│  НЭМС                                                   │
│  ┌─────────────────────────────────────────────────┐   │
│  │ ТУ 3667-013-05608841-2020  [PDF]  [Открыть]    │   │
│  │ Правил: 12  Слотов: 8  Шаблонов: 2             │   │
```

При создании — диалог: выбрать ProductType, указать version, выбрать уже загруженный файл (FileId) или загрузить новый.

## Страница `/technical-conditions/:id` — Детальная страница TC

Центральная страница для работы с ТУ. Три вкладки.

```
ТУ 3667-013-05608841-2020  (НЭМС)
[Правила] [Слоты обозначения] [Шаблоны отображения]
          ─────────────
```

---

### Вкладка «Правила»

Отображает `TechnicalConditionRule[]`. Заполняется воркером, редактируется вручную.

```
[Запустить обработку ТУ]          ← POST /technical-conditions/:id/process
                                    Запускает TCWorker
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[0] 5.1 Диаметр условный                         [Ред.]
    DN 25, DN 32, DN 42, DN 48, DN 57, DN 89...

[1] 5.2 Давление рабочее                          [Ред.]
    | Класс | МПа  | кгс/см² |
    |-------|------|---------|
    | Р6    | 0.63 | 6.3     |
    ...

[2] 5.3 Климатическое исполнение                  [Ред.]
    | Код  | t_min | t_max |
    ...
```

По кнопке «Ред.» — inline редактирование `content` (textarea с поддержкой markdown).
Кнопка «Запустить обработку ТУ» — активна только если есть FileContent для `TC.fileId`.

---

### Вкладка «Слоты обозначения»

Здесь человек:
1. Определяет набор параметров условного обозначения (`DesignationSlot[]`)
2. Привязывает к каждому слоту правила из вкладки «Правила»

```
[+ Добавить слот]

┌─ [0] Диаметр условный ────────────────────────────────┐
│  Привязанные правила:                                  │
│  [5.1 Диаметр условный ×]  [+ Добавить правило]       │
└────────────────────────────────────────────────────────┘

┌─ [1] Давление рабочее ────────────────────────────────┐
│  Привязанные правила:                                  │
│  [5.2 Давление рабочее ×]  [+ Добавить правило]       │
└────────────────────────────────────────────────────────┘

┌─ [2] Климатическое исполнение ────────────────────────┐
│  Привязанные правила:                                  │
│  (нет)  [+ Добавить правило]                          │
└────────────────────────────────────────────────────────┘
```

**«+ Добавить правило»** — открывает Popover со списком правил из вкладки «Правила».
Выбранное правило добавляется в `slot.ruleIds`. Крестик — удаляет.

Слоты сортируются по `index`, перетаскивание для изменения порядка — опционально.

Сохранение через PUT `/technical-conditions/:id/slots` — весь массив целиком.

## Расширение OrderCard — блок «Условное обозначение»

Новый под-компонент `OrderCardDesignation` в `order-card/`.

```
┌─ Условное обозначение ─────────────────────────────────┐
│                                                         │
│  TC: ТУ 3667-013-05608841-2020                         │
│  Шаблон: [Полное ▾]                                    │
│                                                         │
│  НЭМС — 700 — 40 — У1                                  │
│  ──────────────────────                                 │
│                                                         │
│  [0] Диаметр условный          700          ✓ 0.95    │
│  [1] Давление рабочее          40           ✓ 0.88    │
│  [2] Климатическое исп.        У1           ⚠ 0.61    │  ← подсветка
│      Обоснование: "В заявке указан регион Сибирь,     │
│      но явная маркировка климата не указана"           │
│                                                         │
│                         [Запустить анализ]  [Сохранить]│
└─────────────────────────────────────────────────────────┘
```

**Логика отображения:**
- Если `designation.human` задан — показываем его значения (с меткой «Вручную»)
- Иначе — `designation.ai`
- Значения с `confidence < 0.7` — жёлтый фон, раскрывается `reasoning`
- Dropdown «Шаблон» — меняет `DisplayTemplate`, строка обозначения перестраивается на клиенте

**Редактирование вручную:**
Клик на значение параметра → inline input, сохраняется в `designation.human.values[n]`.
Кнопка «Сохранить» → PATCH `/orders/:id/designation`.

**«Запустить анализ»:**
POST `/orders/:id/analyse-designation` → создаёт DesignationWorker.
Статус отображается как у других воркеров (polling через WorkersPage или inline).

## Новые TanStack Query хуки

```typescript
// product-type.query.ts
useProductTypes()
useCreateProductType()
useUpdateProductType()

// technical-condition.query.ts
useTechnicalConditions(productTypeId?)
useTechnicalCondition(id)
useCreateTechnicalCondition()
useProcessTC()          // POST /:id/process → запуск воркера
useUpdateTCSlots()      // PUT /:id/slots
useUpdateTCRule()       // PATCH /:id/rules/:ruleId
useAddTCTemplate()
useUpdateTCTemplate()
useDeleteTCTemplate()

// order.query.ts (расширение)
useAnalyseDesignation() // POST /:id/analyse-designation
useUpdateDesignation()  // PATCH /:id/designation
```
