# Workers — соглашения

## Воркер хранит своё состояние в собственной записи

Каждый воркер сохраняет промежуточные и итоговые данные в своей записи `WorkerData` в БД,
а не только в целевых объектах (FileContent, Order и т.д.).

Это означает:
- **ID внешней операции** (`cloudOperationId`) — сохраняется сразу после запуска, до завершения.
- **Результат операции** (`operationResult`, `orderDetails` и т.п.) — сохраняется при получении, до записи в целевой объект.
- **Ошибка** — сохраняется в воркере параллельно с обновлением статуса целевого объекта.

Это позволяет:
- восстановить воркер после перезапуска сервера (`existingCloudOperationId` в конструкторе);
- отлаживать воркеры в UI без просмотра FileContent/Order;
- понять на каком шаге воркер находится или завис.

## Яндекс-воркеры используют асинхронные операции

Все воркеры, взаимодействующие с Yandex Cloud API, работают по одному паттерну:

1. **Submit** — отправить запрос, получить ID операции, сохранить в WorkerData.
2. **Poll** — цикл `while (!shouldStop)` с проверкой статуса через `pollCompletion`
   или `waitForOperation`. Интервал между итерациями — `sleep(POLL_INTERVAL_MS)`.
3. При получении результата — сохранить в WorkerData, затем обновить целевой объект.

Синхронные HTTP-вызовы (без операции) допустимы только если API явно не поддерживает
асинхронный режим.
